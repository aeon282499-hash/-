# 立花e支店APIで「新しく取れるようになったデータ」棚卸し（2026-09-03）

既存の情報源 = J-Quants（日足10年ローリング・週次信用残・空売り残高報告・信用規制フラグ・財務・指数）。
それと比べて立花APIで **初めて取れる** もの／**既にあるが質が上がる** ものを分けた。

## B. 既にあるが質が上がる

| データ | 今 | 立花で |
|---|---|---|
| 信用残（週次） | J-Quants 週次（`_margin_10y.pkl`） | 同じ週次だが一般/制度/合算の内訳と前週比が付く |
| 予想PER/PBR/ROE/配当利回り | J-Quants 財務から自前計算 | 情報ベンダー値（会社予想ベース）を直接 |
| 貸借区分・前日終値・値幅制限 | J-Quants 銘柄情報 | 翌営業日の値幅上下限が事前に分かる（寄指の指値が値幅内か検証） |

## C. 注意（過去の検証結果との整合）

- 新データを**オーバーレイで足すだけの改善は過去3連敗**（TOPIX地合い/業種空売り比率/混雑）。A の日次データは**まず貯めて、数ヶ月分たまってから**BTで採否を決める。
- 唯一すぐBTできるのは **20年日足**。まず現行ルールをそのまま2001〜2016に当てて「勝てない年が何年あるか」を見る（履歴の長さが変わると『全年プラス』の意味が変わる）。
- 立花APIは共用。時価の高頻度取得は禁止。日次バッチ（11:30/18:25）と単発クエリに限る。

## D. いま動いているもの

- `tachibana_daily_snapshot.py` → `tachibana_snapshots/YYYY-MM-DD_{am,pm}.pkl`（Windowsタスク TachibanaSnapshot_am 11:30 / _pm 18:25、ログオン中のみ）
- `tachibana_fetch_history.py --universe` → `tachibana_history.pkl`（2026-09-03 01:05から自動開始、1〜2時間）
- 読み出し: `from tachibana_daily_snapshot import load_panel; load_panel("syoukin")`
